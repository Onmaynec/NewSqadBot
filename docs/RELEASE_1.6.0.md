# NewSqadBot v1.6.0 — Production & Platform

Релиз посвящён стабильности модулей и локальной веб-панели администратора в чёрно-белом стиле.

## Локальная панель — первый запуск

Панель aiohttp работает в процессе Discord-бота. Использует существующий SQLAlchemy engine и таблицу guild_settings. Токен Discord в браузер не отправляется; второго контейнера и копии БД нет.

1. В Docker Desktop выберите Linux containers. Создайте .env из .env.example и заполните DISCORD_TOKEN.
2. Обновите репозиторий, сохранив копию SQLite:

   git pull origin main

   docker compose exec bot python -m app.ops.backup create

3. Подготовьте образ:

   docker compose build

4. Сгенерируйте **хэш** пароля, введя пароль дважды (минимум 14 символов):

   docker compose run --rm --no-deps --entrypoint python bot -m app.web.auth hash

5. Вставьте строку WEB_ADMIN_PASSWORD_HASH=... из вывода в .env. Пароль не храните в .env.
6. Запустите контейнер: docker compose up -d --build --force-recreate
7. Откройте **http://127.0.0.1:8787** в браузере на компьютере с Docker и войдите с паролем, выбранным на шаге 4.

Без WEB_ADMIN_PASSWORD_HASH панель не запускается: пароля по умолчанию нет. Доступный порт хоста меняется WEB_ADMIN_PORT в .env, порт контейнера фиксирован — 8787.

### Возможности интерфейса

- Выбор ролей и каналов по именам из целевого Discord-сервера, без ручного ввода ID.
- Проверки существования объекта и типа канала, иерархии автоматически выдаваемых ролей и опасных разрешений.
- Параметры Membership, Support, Voice, Leveling, Economy, Quests, Achievements, Events, Suggestions и Statistics.
- Настройка запуска 16 модулей; требуется **перезапуск** для применения изменения списка загружаемых модулей.
- Диагностика доступности Discord/SQLite и ошибок фоновых задач; поиск параметров и удобный мобильный вид.
- Любое сохранение проходит через Database.set_setting и оставляет audit-запись без раскрытия значения.

Веб-панель редактирует только белый список в app/web/catalog.py. Создание новых товаров магазина, конструктор Discord-объявлений, создание панелей ролей и категорий тикетов остаются в специализированных slash-командах. Произвольного SQL-редактора нет.

### Сетевая безопасность

Compose публикует порт **только на 127.0.0.1** хоста (127.0.0.1:8787:8787). Внутри Docker процесс слушает 0.0.0.0, чтобы работал NAT; не удаляйте локальное ограничение в секции ports. Не публикуйте HTTP-сайт в интернет.

Вход: PBKDF2-HMAC-SHA256 (600 000 итераций), HttpOnly/SameSite=Strict cookie, ограничение попыток, CSRF-заголовок, проверка Origin/Host, строгая Content Security Policy. Сессии живут максимум 4 часа и сбрасываются после перезапуска процесса.

Для удалённого сервера используйте SSH port forwarding к localhost удалённой машины, а не публичную публикацию порта. Проверьте настройки firewall и версию Docker.

При потере Discord сохранение новых ролей/каналов блокируется. Если SQLite недоступна, запрос возвращает ошибку вместо фиктивного успеха. Пароли, токены и чувствительные значения не выдаются веб-API.

### Команды диагностики

- docker compose ps
- docker compose logs --tail=200 bot
- docker compose run --rm --no-deps --entrypoint python bot -m app.ops.smoke
- python -m pytest -q
- node --check app/web/static/app.js

## SQLite, WAL и резервные копии

При миграции устанавливается WAL. На каждом SQLite соединении активны foreign_keys=ON и busy_timeout=15000. При старте бот делает quick_check и foreign_key_check.

Restore запрещён, если файл health.json недавно обновлён работающим ботом — включая состояние degraded. ready=false не означает, что БД свободна для замены.

Порядок восстановления:

1. docker compose stop bot
2. docker compose run --rm --no-deps --entrypoint python bot -m app.ops.backup restore /app/data/backups/ИМЯ.db
3. docker compose up -d bot
4. Проверить логи, здоровье SQLite, очередь Scheduler/EventBus и Discord-состояния.

Не используйте docker compose down -v. Не запускайте два процесса бота на одном SQLite volume. Экспортируйте резервные копии за пределы volume.

## Ограничения

Операции Discord API нельзя гарантировать exactly-once при неизвестном исходе доставки. Сайт не заменяет все специализированные интерактивные редакторы Discord. Поддерживается один guild и один процесс SQLite. Успешные автоматические тесты сами по себе не подтверждают ручную приёмку.
