# NewSqadBot v2.1.0 — Member Journey, Support SLA, Voice Rooms 2.0

## Изменения

Этот релиз продолжает локальный вход по паролю из v2.0.0. Discord OAuth и публичный сайт не возвращаются.

**Кандидаты.** До 8 дополнительных типов анкет с собственным вопросом (плюс стандартная форма), выбор типа в Discord, до 12 пунктов индивидуального чек-листа, существующие статусы `pending → in_review → needs_info → approving/rejecting → approved/rejected`, напоминания ответственному через SQLite scheduler. Панель `/application guide` показывает правила, доступные каналы и первые задания; содержимое настраивается в сайте. Discord ограничивает количество полей одного Modal: на тип анкеты добавляется один дополнительный вопрос.

**Приватность.** В статусной истории остаётся факт получения ответа, а не его содержимое. `followup_answer` (до 900 символов) и `extra_answer` (до 240) доступны во время рассмотрения и очищаются после одобрения, отказа или отзыва. Старые события истории до v2.1.0 автоматически не перезаписываются во избежание неожиданных изменений данных; перед публикацией истории старые записи следует проверить отдельно.

**Поддержка.** Приоритеты `low/normal/high/urgent`, срочные обращения первыми в общей очереди, SLA первого ответа и бездействия (разные значения для четырёх приоритетов), уведомления в канал и личные сообщения назначенному сотруднику. Существующий механизм автоматического закрытия за неактивность остаётся отдельным. Категории и распределение по ролям поддержки сохраняются; шаблоны ответов и анонимизированные оценки v2.0/v1.7 продолжили работать.

**Голосовые комнаты.** `/voice preset public|private|team` сохраняет выбор владельца между созданиями; ручные изменения имени, лимита и приватности тоже сохраняются. Discord UserSelect под кнопкой «Пригласить» выдаёт доступ и пытается отправить приглашение в DM. `/voice access` показывает списки разрешённых/заблокированных. При восстановлении бот сверяет сохранённые базовые ACL с Discord, не сбрасывая прочие права участников. `/voice usage` и локальный веб-раздел выводят только ежедневное количество созданных комнат и длительность их существования, без записи разговора или списка посетителей.

**Архитектура.** Большие модули Discord разделены на исполняемые Cogs и отдельные компоненты интерфейса: `membership_views.py`, `tickets_views.py`, `voice_views.py`, `moderation_views.py`. Вынесены независимые сервисы `membership_workflow.py`, `support_sla.py`, `voice_preferences.py`, `moderation_policy.py`, которыми пользуются Discord Cogs и/или HTTP. Добавлены versioned endpoints `/api/v1/membership/*`, `/api/v1/support/*`, `/api/v1/voice/*`, неизменяемый контракт `docs/api_contract_v1.json`. Прежние `/api/portal/*` и `/api/staff/*` остаются совместимыми. Существующие slash-команды и точка загрузки Cog остаются на прежних путях; кнопки, формы и модальные окна находятся в отдельных модулях, а новые бизнес-правила — в сервисах.

**Веб-интерфейс.** Коды старых `obsidian.js` и `obsidian.css` объединены с `app.js` и `style.css`, отдельные устаревшие ассеты удалены. Регрессии Ctrl+K, несохранённых изменений и модальных окон продолжают выполняться на едином коде. В Staff Center добавлены новые вкладки «Кандидаты и адаптация», «SLA поддержки» и «Голосовые 2.0».

## Обновление с v2.0.0

1. Остановите изменение заявок/тикетов, сделайте и проверьте резервную копию SQLite; экспортируйте её из Docker volume. Пример: `docker compose exec bot python -m app.ops.backup create`. Помните, что обычное копирование работающего SQLite без checkpoint может дать неконсистентную копию — используйте встроенный backup.
2. Убедитесь, что `.env` содержит обязательный `WEB_ADMIN_PASSWORD_HASH`; никакого Discord OAuth/Funnel. Если Funnel раньше публиковал localhost, на Windows отключите `tailscale funnel off`.
3. `git pull origin main`, затем `docker compose up -d --build --force-recreate`.
4. Проверьте `docker compose logs --tail=200 bot`; Alembic должен пройти к `0017_member_support_voice`.
5. Откройте `http://127.0.0.1:8787`. Сохраните пробную форму, отметьте чек-лист тестового кандидата, назначьте SLA, создайте тестовую голосовую комнату, проверьте восстановление прав после рестарта.
6. Прогон тестов локально: `python -m pytest -q`, `node --test tests/*.test.cjs`, `npm run test:e2e` при установленном Chromium.

## Откат

Миграция `0017` **аддитивна** (новые таблицы и поля), но коды v2.0.0 не тестировались на схеме v2.1.0 как полноценный путь downgrade. Безопасный откат — **остановить контейнер, восстановить проверенную копию базы до апдейта v2.1.0, переключить Git на конкретный коммит v2.0.0 и пересобрать контейнер**.

```powershell
docker compose down
git checkout 68d68550321afe7a8004bad0273738f7aff993d4
docker compose up -d --build
```

Перед запуском старого кода восстановите базу через документированную процедуру из `docs/OPERATIONS.md`. Не используйте `docker compose down -v`: это уничтожит хранилище. Данные, созданные после точки резервной копии, не войдут в откат. Не используйте необдуманный `alembic downgrade` на production — он удалит новые поля и таблицы.

## QA и нагрузка

- Python (SQLAlchemy/SQLite, проверки прав, история заявок, Voice lifecycle), Node runtime-моделирование, Playwright Chromium, Docker smoke, security.
- `tests/test_v21_load.py`: 40 параллельных записей SQLite (WAL + busy_timeout) и 75 задач scheduler с проверкой однократной обработки, печатаются p50/p95/max задержки.
- Длительность по одному CI-прогону — **не основание немедленно мигрировать на PostgreSQL**. Для такого перехода нужны реальные замеры размеров базы, очереди записи, p95 latency под штатной нагрузкой Windows/Docker и долгосрочные ошибки lock contention.
- Не проводились реальные массовые действия против production Discord Guild. Для ручного приёмочного прогона используйте staging Discord и проверяйте `Forbidden`, потерю соединения, восстановление после рестарта, выход владельца Voice Room и доступ кандидатов.

## Ограничения и контракт

- Вход по-прежнему один локальный пароль, оператор определён `WEB_LOCAL_OPERATOR_ID`.
- Тип анкеты добавляет до одного дополнительного пользовательского поля из-за лимита Discord Modal; это не произвольный конструктор из десятков полей.
- SLA — предупреждения, **не гарантированное время реакции**; при недоступном Discord повтор зависит от scheduler.
- Время голосовой комнаты — время от регистрации до удаления, а **не время активной речи**.
- Сохранённые ACL привязаны к существующей комнате; при удалении комнаты адресные разрешения очищаются. Персональные пресеты владельца остаются.
- Cogs продолжают содержать оркестрацию Discord, но UI-компоненты вынесены в четыре `_views.py`, общие бизнес-операции — в сервисы без нарушения публичных slash-команд.
