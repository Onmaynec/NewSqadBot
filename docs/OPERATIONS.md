# NewSqadBot — эксплуатация v1.6.0

Документ для развёртывания и восстановления бота. README и Issues не используются как техническое задание.

## Docker Desktop / Windows 11

1. Выберите Linux containers в Docker Desktop и проверьте docker info.
2. Создайте .env по образцу .env.example, укажите DISCORD_TOKEN. Никогда не коммитьте .env.
3. Сборка: docker compose build --pull
4. Запуск: docker compose up -d
5. Проверка: docker compose ps
6. Логи: docker compose logs --tail=100 bot

Команда smoke без подключения Discord: docker compose run --rm --no-deps --entrypoint python bot -m app.ops.smoke

## Docker Hub 401 Unauthorized

Отказ на стадии load metadata для python:3.12-slim-bookworm — ошибка загрузки образа из реестра, ещё до выполнения Dockerfile.

Проверка авторизации:
1. docker logout
2. docker login
3. docker pull python:3.12-slim-bookworm

По умолчанию v1.0.0 использует зеркало Docker Official Images на Amazon ECR:
public.ecr.aws/docker/library/python:3.12-slim-bookworm

Для ECR: docker pull public.ecr.aws/docker/library/python:3.12-slim-bookworm
Если ECR недоступен, добавьте в .env PYTHON_BASE_IMAGE=python:3.12-slim-bookworm, пройдите docker login, затем снова выполните docker compose build --pull.

Если оба реестра недоступны, проверить сеть, корпоративный прокси, Docker Desktop, VPN и сетевые блокировки. Не изменять токен Discord: он здесь не участвует.

## Обновление версии

1. Снять резервную копию SQLite.
2. git pull origin main
3. docker compose build --pull
4. docker compose up -d --force-recreate
5. docker compose ps

## SQLite: резервные копии и восстановление

Бот использует SQLite с WAL, поэтому копирование только newsqad.db из работающего контейнера может привести к неполному бэкапу. Используется штатный SQLite Online Backup API.

Создание копии во время работы:
docker compose exec bot python -m app.ops.backup create

Проверка:
docker compose exec bot python -m app.ops.backup verify /app/data/backups/ИМЯ.db

Копии лежат в volume по пути /app/data/backups. Регулярно экспортируйте их за пределы Docker volume: например, через docker cp с идентификатором контейнера из docker compose ps.

Восстановление — только когда основной бот остановлен:
1. docker compose stop bot
2. docker compose run --rm --no-deps --entrypoint python bot -m app.ops.backup restore /app/data/backups/ИМЯ.db
3. docker compose up -d bot
4. Проверить health, логи, права доступа, роли и отложенные операции в Discord.

Restore проверяет целостность backup-файла, сохраняет текущую базу как before-restore-*.db и не выполняется при свежем признаке работы контейнера. Старые изменения, уже применённые к Discord, не откатываются восстановлением SQLite; необходимо сверить состояния.

## Discord и безопасность

Бот ограничен одним guild ID из ТЗ. Токен, персональные сведения и credential store Docker не публиковать.

В Discord Developer Portal включить Server Members Intent; для голосовых модулей нужен Voice States Intent. Message Content — только когда функции реально требуют чтения текста.

Роли бота должны стоять выше управляемых. Для временных комнат нужны Manage Channels и Move Members, для тикетов — Manage Channels и Embed Links, для Membership — Manage Roles, а для изменения ника — Manage Nicknames. Проверяйте channel overwrites.

После запуска:
- /botsettings — серверные настройки и права (администрация);
- /voice diagnose — проверка разрешений и настроек генератора;
- /application status — жизненный цикл заявки;
- /stats settings — начало сбора статистики;
- /suggest settings — панели предложений.

Docker smoke подтверждает загрузку Python-модулей и чистые миграции. Поведение на реальном Discord-сервере необходимо проверять отдельно на разрешённых тестовых аккаунтах, не применяя наказания к случайным пользователям.

## Объявления /ann и справочник /help (v1.1.0)

Вызов объявления доступен владельцу сервера, назначенным владельцам бота и администраторам. 
Команда **/ann** принимает:
- `вид` — «Обычный текст» или «Embed-карточка»;
- `канал` — канал публикации;
- `цвет` — необязательный RGB HEX (#RRGGBB), только для Embed, стандартный #4A86F7.

После выбора параметров открывается одно окно с полями «Заголовок» и «Текст объявления». 
Обычное сообщение поддерживает до 1750 символов текста; Embed — до 3500.
Бот проверяет права в канале перед открытием окна и перед отправкой. 
Массовые упоминания запрещены. После успешной отправки отображается ссылка на сообщение; 
в системный аудит сохраняются автор, канал, тип и ID сообщения, но не полный текст.

Команда **/help** открывает приватную синюю панель. Кнопки «Назад» и «Далее» листают страницы,
список разделов позволяет сразу перейти к нужной группе, «Закрыть» убирает управление.
Справочник использует фактически зарегистрированные slash-команды этой гильдии:
отключённые модули не рекламируются как работающие. Некоторые перечисленные команды доступны
только администрации или участникам с соответствующими правами; эти права продолжают проверяться
при выполнении самой команды.

## Доступ участников — исправление v1.1.1

У NewSqadBot теперь один источник статуса участника: **роль кандидата**.
Если у пользователя **есть** роль кандидата, функции для авторизованных участников недоступны.
Если **нет** роли кандидата, он авторизован независимо от других ролей,
наличия анкеты в базе и старых дат Membership.
Автоматические начисления XP, авторизация личного профиля, экономика, тикеты,
мероприятия, комнаты, предложения и рейтинги используют одинаковое правило.

Обязательно назначьте **«Роль кандидата»** в `/botsettings → Роли`.
Если настройка отсутствует, пользовательские функции закрываются (fail-closed),
чтобы случайно не открыть доступ всем до установки роли.
После одобрения заявки бот по-прежнему снимает роль кандидата и при необходимости
выдаёт роль участника, но наличие второй роли больше **не влияет** на доступ.
Административные права для наказаний, настроек и публикаций проверяются отдельно.


## v1.2.0 — Центр объявлений и справки

Команда /ann сохранена с прежними аргументами: тип, текстовый канал и необязательный
цвет Embed. После двух полей формы бот СОХРАНЯЕТ ЧЕРНОВИК и показывает приватный
предпросмотр, не отправляя сообщение сразу. Кнопки:
- «Опубликовать» — отправка после новой проверки прав и подтверждения статуса;
- «Изменить» — модалка с исходным заголовком и текстом;
- «Отложить» — время формата ГГГГ-ММ-ДД ЧЧ:ММ в TIMEZONE контейнера;
- «Отменить» — запрет отправки, включая уже поставленные в очередь задания.

Дополнительные административные команды:
- /announcements drafts — черновики и записи с известной ошибкой;
- /announcements scheduled — запланированные сообщения;
- /announcements history — результаты и неопределённые отправки;
- /announcements send number:... — опубликовать существующий черновик;
- /announcements edit number:... — изменить черновик или опубликованное сообщение;
- /announcements cancel number:... — отменить ожидающую публикацию;
- /announcements duplicate number:... — новый черновик-копия;
- /announcements preset — стартовый макет обновления, новости или мероприятия;
- /announcements template-save — сохранить шаблон под уникальным slug;
- /announcements templates — сохранённые шаблоны;
- /announcements from-template — создать черновик из шаблона.

При ошибке сети во время отправки статус становится uncertain. Бот не повторяет
такую публикацию автоматически, потому что Discord мог получить исходное сообщение.
Проверьте канал вручную и, только убедившись в отсутствии сообщения, создайте
копию через duplicate. После перезапуска отправки, прерванные в состоянии
sending, также переходят в uncertain.

Расписание хранится в SQLite, задачи повторно регистрируются при загрузке.
Отмена заблокирует публикацию, даже если старое задание останется в планировщике.
Если планировщик перестал регистрировать задачу из-за сбоя, перезапуск
восстанавливает ожидающие записи scheduled. Дату со спорным временем DST нужно
заменить на существующее однозначное местное время.

Справочник /help: поиск по названию и описанию, детали параметров,
навигация по категориям без лимита в 25 разделов. Обычные команды
показываются согласно роли кандидата; список в справочнике не заменяет
реальную ACL-проверку при выполнении команды.

В /botsettings добавлены «Объявления» и «Диагностика».
Проверка показывает конфигурацию кандидата, иерархию ролей, каналы и доступы
бота без изменения состояния Discord.

Миграция: 0013_announcements. Перед обновлением создайте резервную копию SQLite.
Запуск: git pull origin main; docker compose up -d --build --force-recreate.


## v1.5.0 — Core Stability & Reliability

### Старт, восстановление и завершение

Перед миграциями проверяется возможность записи в DATA_DIR реальным созданием временного файла. После миграций выполняются SQLite quick_check и foreign_key_check; некорректная БД блокирует запуск. SIGTERM/SIGINT инициируют bot.close(), остановку Scheduler/EventBus и закрытие соединений SQLite. Повторные Discord on_ready/on_resumed не создают второй экземпляр фоновых процессов.

Ошибки загрузки отдельных модулей сохраняются в module_states и отображаются в диагностике. Состояния основного процесса фиксируются атомарно в /app/data/health.json: ready, timestamp, phase, version, discord, sqlite, scheduler, event_bus, module_errors. Значения phase: starting, ready, degraded, discord_disconnected, stopping. Используйте docker compose ps и docker compose logs --tail=150 bot.

### Scheduler и EventBus

В /botsettings → Диагностика видны просроченные и зависшие задачи, ошибки планировщика, ожидания EventBus, число квитанций и типы событий без обработчика. Scheduler обрабатывает один проход за раз и атомарно захватывает задачи через SQLite. После ошибки обработчик повторяется с задержкой, после пяти неудач задача получает статус failed. Незавершённые задания после остановки повторяются по истечении lease.

Завершённые ключи scheduled_jobs не удаляются автоматически, поскольку это нарушило бы защиту от повторного выполнения. EventBus перескакивает заблокированные старые страницы через сохраняемый курсор сканирования; раз в 30 минут удаляет квитанции старше 30 дней, только если события нет в outbox. Отсутствие подписчика не приводит к потере нестандартного события.

Важно: при неизвестном исходе запроса Discord нельзя гарантировать exactly-once; обработчики внешних действий должны быть идемпотентны. Отложенные объявления с неопределённой отправкой не отправляются автоматически повторно.

### SQLite, volume и восстановление

Для async SQLite установлен 15-секундный timeout блокировок. Транзакции, продолжающиеся более двух секунд, отмечаются в логах. Выполняются тесты повторной миграции заполненной БД, резервирования/restore, одновременных операций и повторного захвата задач.

Один SQLite volume предназначен для одного экземпляра NewSqadBot. Не используйте docker compose down -v. Копии из /app/data/backups нужно дополнительно экспортировать за пределы volume.

Диагностика:
- docker compose logs --tail=150 bot
- docker compose ps
- docker compose run --rm --no-deps --entrypoint python bot -m app.ops.smoke
- docker compose exec bot python -m app.ops.backup create
- docker compose exec bot python -m app.ops.backup verify /app/data/backups/ИМЯ.db

На Discord-сервере: /botsettings → Диагностика.

Большинство голосовых функций, наград, розыгрышей и управления тикетами уже присутствуют в предыдущих релизах. Проверка на живом Discord-сервере должна проводиться отдельно.

## v1.9.0 — автоматическое резервирование и диагностика

При запуске бот начинает отдельную задачу `BackupWorker`: snapshot через SQLite Online Backup API, проверка восстановления во временную БД и экспорт в host-directory. Период по умолчанию — 24 часа, ротация — 7 последних **автоматических** копий. Ручные архивы и `before-restore-*` не очищаются.

В `compose.yaml` подключён каталог хоста `${BACKUP_EXPORT_HOST_DIR:-./backups}` → `/app/backup-export`. Перед обновлением создайте этот каталог с правами записи для пользователя `bot`. На Linux можно выполнить `docker compose run --rm --no-deps --user root --entrypoint sh bot -c 'chown bot:bot /app/backup-export && chmod 700 /app/backup-export'`; на Docker Desktop для Windows проверьте права файла в общем каталоге. Для вынесения экспорта на отдельный диск укажите абсолютный `BACKUP_EXPORT_HOST_DIR` в `.env`. Каталог не должен находиться внутри `DATA_DIR` контейнера. Никогда не публикуйте бэкапы в репозитории или через веб-сервер.

Ручной прогон и проверка экспортного файла:

```powershell
docker compose exec bot python -m app.ops.automatic_backup run-once
docker compose exec bot python -m app.ops.automatic_backup probe /app/backup-export/ИМЯ_КОПИИ.db
```

При отсутствии права записи экспорт не выполняется, а журнал бота фиксирует ошибку. Локальный snapshot сохраняется в `/app/data/backups`. Ротация применяется к автоматическим снимкам даже после ошибки экспорта. Данные рабочего SQLite не изменяются проверкой restore-probe.

Веб-консоль → Диагностика содержит: состояние Discord Gateway, последние подключения/обрывы, количество HTTP-ошибок, последние события восстановления, состояние Scheduler/EventBus и очередей, SQL-запросы (медленные от 500 мс), статус бэкапов. `/app/data/operations.json` хранит до 40 служебных событий и агрегаты без токенов/содержимого переписки. Обновлённый `health.json` остаётся совместим со старым healthcheck.

**Эксплуатационные ограничения:** Discord.py скрывает успешно обработанные внутренние 429/повторы — HTTP-счётчик показывает только исключения, дошедшие до приложения. Scheduler и EventBus обеспечивают at-least-once, а не exactly-once для внешних Discord API. В случае падения при отправке объявления статус `uncertain` требуется сверить вручную, а не повторять публикацию вслепую.

Релизный runbook, настройки и приёмка: [RELEASE_1.9.0.md](RELEASE_1.9.0.md).
