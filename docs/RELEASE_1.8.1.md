# NewSqadBot v1.8.1 — Stability & Regression

Тип: **patch release**. Цель: закрепить Obsidian Web Console, расширить автоматическую проверку Discord-сценариев и восстановить документацию установки.

> Подготовленный текст первого GitHub Release. Публикация релиза и установка на рабочий Discord-сервер разрешаются только после зелёного CI и ручной проверки из раздела «Приёмка». Автоматические тесты не подменяют реальные Discord API и браузер.

## Исправлено

- Навигация через Ctrl/Cmd+K возвращает фокус на исходный элемент **до** проверки несохранённых настроек. При отмене перехода фокус не остаётся на скрытом поле палитры.
- Оставлена прежняя защита от повторной записи класса `sidebar.open` внутри MutationObserver. Добавлены сценарии повторных переключений авторизации/мобильного меню, чтобы не вернуть зависание вкладки.

## Автоматические регрессии

- `tests/obsidian_interactions.test.cjs`: Ctrl+K только после входа; поиск и выбор пунктов и настроек; навигация клавиатурой; ограничения по ролям; фокус и клавиши модальных окон; повторные мутации без зависания.
- `tests/web_unsaved_runtime.test.cjs`: исполнение настоящих `navigate()` / `confirmDiscard()` из `app.js`; отказ от перехода без сброса черновика; подтверждение потери изменений; блокировка перехода во время сохранения; `beforeunload`.
- `tests/test_v181_voice_roles.py`: симулированный жизненный цикл голосовой комнаты (вход, создание, настройка, передача, удаление); запрет управления при Discord Forbidden; повторная автоматическая выдача ролей и запрет для кандидатов; ошибка выдачи роли для повторной обработки.
- Существующие тесты модулей, миграций и веб-API остаются частью общего прогона.
- CI запускает **все** Node-тесты `tests/*.test.cjs` вместо одного файла.

## Защита и зависимости

- Добавлена проверка отслеживаемых Git-файлов на типичные токены Discord/GitHub, webhook URL, приватные ключи и случайно добавленные файлы `.env`/ключи. Значения потенциальных секретов никогда не печатаются в логе сканера.
- В GitHub Actions добавлена независимая проверка известных уязвимостей основных и транзитивных Python-зависимостей через `pip-audit`.
- Аудит обнаружил `PYSEC-2026-2270` в `python-dotenv==1.2.1`; зависимость обновлена до `1.2.4`. Проверить итоговый повторный аудит в CI.
- CI обновлён на `actions/checkout@v6` и `actions/setup-python@v6` (Node.js 24), а checkout больше не сохраняет учётные данные для последующих Git-команд.
- Никаких токенов или OAuth Client Secret в код/документацию не добавлено. Автоматическая проверка **не** удостоверяет отсутствие секретов во всей истории коммитов; при подозрении на утечку требуется ротация.

## Обновление существующей установки

Сначала сохраните SQLite:

```powershell
docker compose exec bot python -m app.ops.backup create
```

Затем обновите код и контейнер:

```powershell
git pull origin main
docker compose up -d --build --force-recreate
docker compose ps
docker compose logs --tail=150 bot
```

Откройте веб-консоль; Ctrl+K, переходы и изменения настроек должны работать. **Не используйте `docker compose down -v`**: это удаляет данные SQLite.

## Чистая установка

1. Установите Docker Desktop с Linux containers.
2. Склонируйте репозиторий; скопируйте `.env.example` в `.env`.
3. Укажите Discord-токен и настройте локальный пароль или Discord OAuth. Для локального пароля сгенерируйте хеш командой `python -m app.web.auth hash` внутри контейнера (см. README).
4. Запустите `docker compose up -d --build`.
5. Убедитесь в успешных миграциях и отсутствии ошибок в логах.
6. Выполните `docker compose run --rm --no-deps --entrypoint python bot -m app.ops.smoke`.
7. Настройте роль кандидата, категории и права Discord через `/botsettings`; проверьте реальное вступление, выдачу ролей и комнату-генератор.

## Известные ограничения

- Реальный Discord E2E требует тестового Guild и корректных разрешений; на GitHub Actions используется имитация Discord API.
- DOM-тесты Node не являются полноценными визуальными тестами в Chrome/Firefox.
- Веб-панель остаётся односерверной и совмещённой с процессом бота.
- Резервная копия внутри Docker volume не защищает от потери самого volume — копии необходимо экспортировать наружу.
