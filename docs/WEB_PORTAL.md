# Веб-панель NewSqadBot v2.0.0 — только localhost

В NewSqadBot v2.0.0 отключены **Discord OAuth** и режим публичного доступа через **Tailscale Funnel**. Панель Obsidian/Staff Command Center работает локально на компьютере с Docker и требует пароль.

## Адрес

- Локально: `http://127.0.0.1:8787` (либо порт `WEB_ADMIN_PORT`).
- Внешний адрес `.ts.net`, OAuth callback и публичные прокси **не поддерживаются**.
- В `compose.yaml` используется проброс **`127.0.0.1:8787:8787`**. Приложение внутри контейнера слушает `0.0.0.0:8787`, чтобы работать через Docker, но наружу порт публикуется только на loopback хоста.

> Настроенный ранее Tailscale Funnel может продолжать проксировать loopback-порт. На хосте выполните `tailscale funnel off` и отключите/удалите старую настройку Funnel. Проверьте отсутствие публичной публикации в панели Tailscale. Приложение не способно автоматически отключить Funnel на вашей ОС.

## Подготовка

1. Создайте файл `.env` по примеру `.env.example`.
2. Укажите Discord bot token.
3. Создайте пароль длиной от 14 символов и получите PBKDF2-хеш:

   ```powershell
   docker compose build
   docker compose run --rm --no-deps --entrypoint python bot -m app.web.auth hash
   ```

4. Скопируйте **только хеш** в `WEB_ADMIN_PASSWORD_HASH`.
5. Удалите `WEB_DISCORD_CLIENT_ID`, `WEB_DISCORD_CLIENT_SECRET`, `WEB_PUBLIC_URL`. Если они останутся заполненными, приложение откажется запускаться.
6. `WEB_LOCAL_OPERATOR_ID=0` использует владельца Discord-сервера. Для назначения другого оператора укажите его настоящий Discord ID, убедитесь в его членстве и правах на сервере.
7. Выполните `docker compose up -d --build`. Откройте `http://127.0.0.1:8787`.

## Безопасность

- Все изменяющие API требуют HTTP Origin с локального сайта и CSRF-токен из текущей сессии.
- Cookies: HttpOnly, SameSite=Strict, ограниченное время действия. OAuth-cookies и токены Discord пользователей не используются.
- После пяти неудачных попыток с одного адреса вступает в силу ограничение входа.
- Пароль открывает права **локального владельца**. Это не система нескольких персональных логинов сотрудников: `WEB_LOCAL_OPERATOR_ID` только определяет Discord-участника, чьи права/ID используются при изменениях и аудите.
- Журнал Staff Command Center маркирует операции как `origin=local_password`. Он не утверждает, что конкретный человек вошёл через Discord.
- Не подключайте reverse proxy, Cloudflare Tunnel, Tailscale Funnel или перенаправление портов на этот сайт.
- При потере доступа с другого компьютера используйте Windows Remote Desktop (если доверяете компьютеру и сети) или работайте непосредственно за машиной-хостом; сам веб-сервер остаётся локальным.

## Ошибки

- `WEB_ADMIN_PASSWORD_HASH обязателен`: парольный хеш не указан или недействителен.
- `удалите WEB_DISCORD_*`: в `.env` сохранилась старая OAuth-конфигурация.
- `Локальный оператор недоступен`: бот не подключён к Discord, ID отсутствует на сервере или участник не загружен. Проверьте `WEB_LOCAL_OPERATOR_ID` и состояние Gateway.
- `HTTP 421`: открытие по недопустимому Host или попытка обратиться через внешнюю ссылку.
- `HTTP 403`: отсутствует CSRF, неподходящий Origin или старый OAuth-сеанс. Повторно войдите по локальному паролю.
