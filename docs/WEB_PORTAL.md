# NewSqad Web Portal — инструкция по удалённому доступу

## Возможности

Панель запускается внутри существующего контейнера NewSqadBot. Никакая отдельная база, перепубликация токена бота или внешний хостинг не нужны.

- Discord OAuth2 с scope `identify` и повторной проверкой роли текущего пользователя через бота **при каждом API-запросе**.
- Роли сайта определяются на основании Discord Guild ID 1439347293076586638 (никакого ручного присвоения прав в браузере).
- Заявки: просмотр и история, взять в работу, уточнить, одобрить, отклонить, повторить незавершённое решение.
- Тикеты: список открытых обращений, приватная история последних 50 Discord-сообщений, ответы в Discord, назначение сотрудника, передача и безвозвратное закрытие.
- Сотрудники: должность и онлайн-статус **только когда включён Presence Intent**.
- Участники: поиск по локальному кэшу сервера, дата входа, список ролей.
- Статистика, рейтинги с сохранением приватности профилей, аудит и агрегаты активности администраторов.
- Owner сохраняет все старые настройки и диагностику. Остальные роли не видят и не могут вызывать API конфигурации.

## Как обойтись без покупки домена

Tailscale Funnel создаёт публичный стабильный HTTPS-адрес вида https://my-pc.my-tailnet.ts.net и проксирует его на локальный порт компьютера. **Это публичный адрес: любой может открыть страницу входа, но внутренние данные и действия требуют Discord OAuth и подходящей роли**. Защита Windows, обновления Docker/Tailscale и сохранность OAuth client secret остаются ответственностью владельца.

1. Установить [Tailscale](https://tailscale.com/download) на ПК с Docker Desktop, войти в свой tailnet. В настройках tailnet должны быть включены MagicDNS, HTTPS и разрешение использовать Funnel.
2. **До публикации порта** найти собственное DNS-имя ПК: в Tailscale Admin Console → Machines → ваш компьютер. Оно имеет вид `my-pc.my-tailnet.ts.net`. Скопируйте **реальное** имя с вашей машины; показанное здесь — лишь пример. Суффикс `.ts.net` предоставляет Tailscale, собственный домен покупать не требуется.
3. В [Discord Developer Portal](https://discord.com/developers/applications) открыть приложение **этого бота**, раздел OAuth2. Скопировать Client ID и сгенерировать Client Secret. **Client Secret никогда не отправлять в чат и не публиковать в GitHub.**
4. В списке OAuth2 Redirects добавить адрес по своему реальному DNS-имени:

   `https://my-pc.my-tailnet.ts.net/auth/callback`

5. Записать в локальный `.env` (без кавычек):

   ```env
   WEB_DISCORD_CLIENT_ID=ВАШ_CLIENT_ID
   WEB_DISCORD_CLIENT_SECRET=ВАШ_CLIENT_SECRET
   WEB_PUBLIC_URL=https://my-pc.my-tailnet.ts.net
   ```

   URL не должен иметь завершающий слэш или `/auth/callback`. Все три значения обязательны. OAuth-режим **отключит парольный вход**; доступ по ролям начнёт проверяться сервером.
6. Перезапустить контейнер и убедиться по логам, что web-панель запущена:

   `docker compose up -d --build --force-recreate`

7. Только **после подготовки OAuth** открыть PowerShell на компьютере с ботом и включить публичный HTTPS Funnel:

   `tailscale funnel --bg 8787`

8. Скопировать фактически выданный Tailscale адрес и убедиться, что он **точно совпадает** с `WEB_PUBLIC_URL`. Если адрес отличается, сразу выключить Funnel командой `tailscale funnel --bg 8787 off`, исправить OAuth Redirect URI и `.env`, перезапустить бота и только после этого включить Funnel заново.
9. Открыть выданный HTTPS-адрес и нажать **Войти через Discord**. Discord перенаправит пользователя обратно на сайт, после чего бот проверит его текущие роли на NewSqad.

**Не включайте Funnel, пока действует парольный локальный режим**. Публичный URL доступен всему интернету, хотя информация и действия после настройки защищены OAuth и разрешениями Discord.


**Примечание о локальном адресе.** В OAuth-режиме вход на http://127.0.0.1:8787 автоматически отправит браузер на HTTPS-адрес Tailscale перед авторизацией: Discord не может возвращать Secure cookie на другой HTTP-hostname. Пользуйтесь публичным HTTPS-адресом при входе.

Пароль WEB_ADMIN_PASSWORD_HASH можно оставить в .env для возможного возвращения к локальному режиму, но пока включён Discord OAuth, вход по этому паролю отключён. Для отключения внешнего доступа выполните `tailscale funnel --bg 8787 off` и удалите настройки WEB_DISCORD_CLIENT_ID/SECRET/URL. Не заменяйте порт в compose.yaml на 0.0.0.0.

## Discord intents и приватность тикетов

Для отображения текстов Discord-сообщений в тикетах нужно включить **Message Content Intent** в Discord Developer Portal → Bot → Privileged Gateway Intents, а в .env задать `ENABLE_MESSAGE_CONTENT_INTENT=true`. Боту также нужны View Channel, Read Message History и Send Messages в приватных тикетах. Без соответствующих разрешений и intent часть текста может быть недоступна — сайт не обходит ограничения Discord.

Для онлайн-статуса сотрудников нужно включить **Presence Intent** в Discord Developer Portal и `ENABLE_PRESENCE_INTENT=true` в .env, перезапустить бота. Если presence не доступен, отображается **Неизвестно**, а не «Офлайн». Список сотрудников зависит от участников, известных кэшу Gateway; он не гарантирует полный перечень до завершения загрузки участников Discord.

**Чат тикета:**
- HTTP-ответ возвращает до 50 последних сообщений из текущего Discord-канала, а интерфейс обновляет их при открытом чате.
- Сообщения от staff отправляются **ботом** с подписью сотрудника; сайт не может выдавать себя за аккаунт сотрудника.
- Данные сообщений не сохраняются сайтом в SQLite и не включаются в аналитические таблицы или audit. При закрытии бот удаляет канал и стирает данные тикета как прежде. Транскриптов и архивирования нет.
- В журнале действий можно учитывать только тип операции и ID, не содержимое сообщения.

## Проверка безопасности и запуск

- Проверить `docker compose ps` и `docker compose logs --tail=150 bot`.
- Убедиться, что /api/session без входа отвечает authenticated=false, а /api/bootstrap без сессии запрещён.
- Проверить вход Owner и запрет настройки из Admin/Moder/Ticket Staff.
- Удалить роль у тестового аккаунта в Discord и убедиться, что следующий запрос получает запрет.
- Проверить запрет чтения /api/portal/audit для Moder/Ticket Staff и /api/portal/members для Ticket Staff.
- Проверить историю и ответ в тестовом тикете; после закрытия проверить отсутствие Discord-канала и SQLite-обращения.
- Повторить OAuth login после рестарта; сессии сбрасываются при перезапуске.
- Отключить Funnel после теста, если публичный доступ больше не требуется.


## Рабочие разделы веб-портала

### Owner — конфигурация и редакторы Discord

- **Настройки**: роли, каналы, модули, Membership, XP, экономика, статистика и другое; сохранение всех полей страницы одним подтверждением.
- **Магазин NS Coins**: титулы и декоративные роли, цены, ограничения остатков, включение и снятие с продажи. Опасные и недоступные по иерархии роли запрещены.
- **Панели ролей**: черновики, выбор канала, добавление/удаление безопасных ролей, несовместимые пары, публикация/обновление/отключение.
- **Правила ролей**: автоматическая выдача при принятии участника и роли-награды за уровни.
- **Категории поддержки**: создание, включение/отключение, возможность обращения кандидатов.
- **Объявления**: черновики текста/Embed, предпросмотр, редактирование, расписание, отправка с подтверждением, отмена, копия и шаблон. При неопределённом Discord-ответе система не утверждает успешную отправку.

### Owner и Admin — операции с сообществом

- **Мероприятия**: создание, публикация, регистрации, подтверждение участия с существующим атомарным начислением XP и NS Coins, отмена.
- **Розыгрыши**: создание, публикация, выбор победителей после повторной проверки допуска, повторный выбор с причиной.
- **Предложения**: категории, фильтры, решение с причиной и уведомление автора.
- **Временные голосовые комнаты**: мониторинг, смена названия/лимита, доступ/видимость, исключения доступа, передача владельца, удаление пустой комнаты.
- **Поиск команды**: список действующих групп и их административное закрытие с очисткой связанных ресурсов.
- Статистика сервера, рейтинги с учётом приватности, аудит, статистика работы администрации.

### Owner, Admin и Moder — модерация

- **Ручные наказания из сайта**: warn, mute, kick, ban с проверкой иерархии Discord.
- Поиск дел по номеру, пользователю, типу и статусу; карточка, срок, исполнитель, история изменений.
- Редактирование причины, изменение срока и отмена с обязательной причиной и подтверждением. Серверные блокировки защищают от одновременных изменений одного дела.

### Все четыре staff-роли — заявки и тикеты

- Анкеты: просмотр, история, уточнение, назначение/передача сотруднику, одобрение, отказ с причиной и повторение прерванных шагов.
- Обращения: список, приватный чат из живого Discord, ответ ботом с подписью сотрудника, назначение, приглашение/удаление участников с откатом прав Discord при ошибке, закрытие и удаление канала.
- **Приватность**: сообщения тикетов не архивируются в SQLite, не создаются транскрипты, закрытый тикет и его переписка не сохраняются.

### Проверка перед публичным включением

- [ ] Owner может сохранять роли/каналы, работать с панелями и магазином.
- [ ] Admin видит аналитику, аудит и мероприятия, но не имеет доступа к конфигурации, магазину и панелям.
- [ ] Moder может выдать тестовое предупреждение и отменить его, не видит аудит.
- [ ] Ticket Staff может открыть тикет и заявку, но не видит остальные разделы.
- [ ] Удаление staff-роли в Discord немедленно закрывает доступ на следующем API-запросе.
- [ ] Работают проверка сроков наказаний, Discord-уведомления и восстановление после рестарта.
- [ ] Кнопки выключенной панели выбора ролей удалены из сообщения Discord.
- [ ] Discord-канал тикета удаляется при закрытии, сообщения и транскрипты не сохраняются.
- [ ] Проверены права бота Manage Channels, Manage Roles, Moderate Members, Ban Members.
- [ ] Проверено восстановление SQLite из backup на копии рабочей базы.
- [ ] Проверен OAuth по публичному HTTPS из внешнего браузера.

**Ограничения:** работа происходит только в одном Discord guild. Реальный OAuth/Tailscale и Discord permissions требуется настроить и проверить на машине владельца. В локальном парольном режиме доступны конфигурационные действия; операции с участниками и публикациями требуют идентифицированного Discord OAuth сотрудника. Не гарантируется exactly-once отправка внешнего Discord API при потере соединения. Историческая аналитика удалённых тикетов недоступна по требованиям приватности.


### Безопасный конфигурационный режим без OAuth

Если WEB_DISCORD_CLIENT_ID/SECRET/URL пусты, существует только прежняя localhost-панель с PBKDF2-паролем. **Не включайте Funnel в таком режиме**: внешние OAuth-роли ещё не действуют, и парольный вход предназначен исключительно для localhost.
