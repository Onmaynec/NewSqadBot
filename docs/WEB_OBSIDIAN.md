# NewSqadBot — Obsidian Web Console

Новая визуальная система для веб-панели NewSqadBot. Основа — монохромная админ-панель Obsidian: тёмный фон, читаемая иерархия, компактная навигация, акцент только на текущем действии.

## Что изменено

- Общий слой Obsidian CSS применяется поверх прежней таблицы стилей ко всем страницам: обзор, заявки, тикеты, команда, модерация, аналитика, аудит, мероприятия, магазин, роли и конфигурация.
- Навигация разбита на рабочую область, управление, аналитику, конфигурацию и систему. Пункты по-прежнему формируются на основании серверного набора разделов для Discord-роли.
- Поиск Ctrl + K / Cmd + K открывает палитру переходов. Результаты можно выбирать мышью, стрелками и Enter; Esc закрывает окно.
- По умолчанию поиск показывает доступные разделы. Owner также может искать параметры конфигурации по имени, ключу и группе. Переход к параметру открывает соответствующую страницу и фильтрует карточки по конкретному ключу.
- Смена страницы из палитры использует ту же функцию navigate() и проверку несохранённых изменений, что и обычные кнопки навигации. Параметры сайта не сохраняются автоматически.
- Для узких экранов добавлены подложка бокового меню, корректное состояние aria-expanded, адаптивный поиск и компактные KPI.
- Уменьшенное движение (prefers-reduced-motion) отключает декоративные анимации. Для клавиатурной навигации добавлены индикаторы фокуса и ссылка «Перейти к содержимому».

## Совместимость

Бизнес-логика Python, SQLite, Discord OAuth, API и модель прав не меняются. Новая палитра использует только список разделов, уже созданный клиентом по роли пользователя. Сервер продолжает перепроверять роль при API-запросах. Видимость ссылки в интерфейсе не является проверкой прав.

Важные ограничения текущей версии:

- Сайт остаётся односерверным.
- Переписки удалённых тикетов не сохраняются; палитра не индексирует приватные сообщения.
- Данные Live Dashboard обновляются существующими механизмами, не имитируются новой темой.
- Действия удаления, публикации и изменения ролей по-прежнему выполняются через существующие формы и API. Палитра является навигацией, а не обходом подтверждений.
- Новая система стилей загружается после старого CSS и не удаляет устаревшие правила. Полная декомпозиция старой CSS-базы — отдельный технический этап после проверки экранов с живыми данными.

## Ручная приёмка

1. Owner: проверить главную страницу, настройки, магазин, редакторы, аналитику, аудит и диагностику. Открыть поиск по Ctrl + K, ввести ключ настройки, проверить фильтрацию и фокус поля.
2. Изменить настройку и не сохранять её. Через глобальный поиск попробовать перейти на другую страницу: окно подтверждения должно остаться рабочим. Отмена не должна терять изменения.
3. Admin/Moder/Ticket Staff: войти через Discord OAuth и проверить, что поиск не показывает чужие настройки или закрытые разделы, прямые API-запросы запрещены по текущей роли.
4. Понизить роль пользователя в Discord и сделать новый запрос: доступ должен пересчитаться сервером. Визуальная палитра не заменяет проверку API.
5. Создать тестовый тикет, ответить в чате, назначить сотрудника и закрыть. После закрытия канал удаляется, содержимое переписки не сохраняется в базе.
6. Проверить Live Dashboard, уведомления, отсутствие фальшивого онлайн-статуса без Presence Intent.
7. Проверить экран 1440px, планшет 768px и мобильный 390px: нет горизонтальной прокрутки, меню открывается и закрывается, окно поиска доступно с клавиатуры.
8. Включить уменьшенное движение в ОС, проверить отсутствие декоративных анимаций.

Запуск и обновление остаются прежними, см. docs/WEB_PORTAL.md. CI подтверждает синтаксис Python/JS, модульные тесты и сборку Docker; реальная проверка разрешений Discord и визуальная приёмка обязательны перед выпуском.

## Следующая итерация: рабочие очереди и надёжность

- В заявках добавлены компактные статусы, фильтры, поиск по текущей загруженной странице, кнопка обновления, счётчики и состояние ошибки с повторным запросом.
- В тикетах добавлены фильтры «Все», «Без ответственного», «Мои» и «В работе». Фильтры рассчитываются на сервере по всему выбранному набору обращений и учитывают Discord ID сотрудника. В локальном парольном режиме персональный фильтр недоступен.
- API заявок и тикетов поддерживает валидируемый параметр page (1–9999), возвращает page, page_size=100, total и has_next. Старый контракт items оставлен без изменения. Это позволяет просматривать старые обращения, не загружая всю базу сразу.
- В чате тикета повторные обновления не накладываются друг на друга. При временной ошибке существующие сообщения не стираются; выводится отдельное состояние связи. Ответ нельзя отправить повторно, пока операция не закончилась.
- Текст неотправленного ответа остаётся только в поле ввода текущей страницы: он не сохраняется в LocalStorage, IndexedDB, SQLite или журнале. Перед уходом с открытого чата показывается предупреждение, если текст ещё не отправлен.
- Главная страница получила быстрые переходы к заявкам, тикетам и уведомлениям по реальным показателям API. Индикатор состояния инфраструктуры отражает результат проверки служб, а не фиксированную надпись.
- Новые интеграционные тесты проверяют порядок страниц, общее количество, изоляцию по guild, валидацию номера страницы и выборку личных/назначенных/неназначенных тикетов.

**Поиск и пагинация:** строка поиска по заявкам и темам тикетов теперь применяется ко всей выборке на сервере, как и фильтр ответственного. Параметр q ограничен 80 символами, LIKE-символы воспринимаются буквально. Переписка Discord не индексируется и не сохраняется.

## Доступность и выпуск

- Единый менеджер диалогов для управления и поддержки: закрытие по Escape/нажатию на подложку, клавиатурный цикл Tab, возврат фокуса; отдельное предупреждение о несохранённых изменениях поддерживает Escape.
- Состояние загрузки оформлено в чёрно-белой теме, движение отключается при prefers-reduced-motion.
