# NewSqadBot v2.2.0 — отдельный магазин заказов

## Назначение

Модуль `store` — **отдельный от игрового /shop за NS Coins** магазин товаров и услуг с реальными ценами. Покупатель открывает закреплённую Discord-витрину, выбирает товар, указывает количество и оставляет заказ. Бот показывает номер заказа, сообщает продавцу и ведёт историю статусов. **Бот не списывает деньги, не проверяет банковские платежи, не создаёт Nitro-коды, не управляет пользовательскими аккаунтами, не выдаёт бусты автоматически.** Оплату и передачу товара продавец выполняет и проверяет сам.

Допустимые предложения могут включать *законно полученные подарочные подписки Nitro*, стандартные цифровые товары и услуги. Не размещайте предложения с чужими аккаунтами, токенами, фальшивыми подарками, искусственными бустами или иными нарушениями правил Discord. Discord не является стороной этого магазина.

## Первый запуск

1. **Сделать и проверить backup** SQLite перед обновлением. Из Docker:
   ```powershell
   docker compose exec bot python -m app.ops.backup create
   ```
   Не копируйте одну рабочую SQLite-базу напрямую в обход online backup.
2. `git pull origin main`, затем `docker compose up -d --build --force-recreate`.
3. Проверьте `docker compose logs --tail=150 bot`: Alembic head должен стать `0018_private_store` и новый модуль `store` должен иметь статус `active`.
4. В Discord создайте **закрытый текстовый канал для заказов** (например, `#store-orders`), невидимый для роли @everyone. Боту нужны View Channel, Send Messages и Embed Links; владельцу — доступ к каналу.
5. Используйте **`/store settings orders_channel:#store-orders`**. Команда отклонит публичный канал или недостаточные права.
6. Добавьте инструкцию: **`/store payment instruction:<текст оплаты>`**. Не вставляйте платёжные пароли, секретные ключи, номера банковских карт клиентов и Discord-токены.
7. Создайте товары, например:
   - `/store add sku:nitro_1m title:"Nitro Gift — 1 месяц" price:399.00 currency:RUB category:nitro_gift stock:3`
   - `/store add sku:boost_2 title:"Бусты сервера — 2 шт." price:299.00 currency:RUB category:server_boost stock:-1`
   - `-1` означает выполнение под заказ, а не 0 доступных кодов.
   - Это **примеры ввода**, не предлагаемые рыночные цены.
8. Создайте общий канал (например, `#shop`) и выполните `/store panel channel:#shop`. Панель содержит кнопки «Открыть каталог» и «Мои заказы». Команда `/store catalog` работает и без панели.

Веб-консоль на `http://127.0.0.1:8787` → **«Магазин заказов»** позволяет редактировать название, описание, цену, валюту, остаток, видимость и порядок товаров, настраивать инструкцию/канал, проверять заказы и статистику. Только локальный пароль, с CSRF-защитой. Смена канала через веб-панель тоже проверяет приватность и права бота.

## Сценарий заказа

1. Покупатель нажимает «Открыть каталог» (ответ виден только ему).
2. Выбирает товар и количество (1–10) в модальном окне.
3. Видит окончательную стоимость и нажимает «Подтвердить заказ».
4. База атомарно резервирует остаток товара, создаёт заказ `#00001`, сохраняет цену и валюту на момент оформления, создаёт событие журнала.
5. Бот публикует карточку в *закрытом канале продавца*; покупатель получает инструкцию и может открыть `/store order number:<номер>`.
6. Покупатель после самостоятельной оплаты нажимает «Я оплатил». Статус `payment_reported` означает **только заявление покупателя**.
7. Продавец проверяет деньги вне Discord и нажимает «Оплата проверена» в закрытом канале либо `/store status` / кнопку локальной веб-консоли.
8. Когда товар реально передан/услуга оказана, продавец нажимает «Выполнен». Бот уведомляет покупателя в DM, если он разрешён.
9. До проверки оплаты покупатель может отменить заказ, после — отмена доступна только продавцу. При отмене ограниченный остаток возвращается в наличие ровно один раз.

Каналы заказов не являются платёжным шлюзом или доверенным доказательством оплаты. Инструкция в боте — **информация**, не счёт, не автоматическое списание. Для возврата средств действуют внешние договорённости продавца и покупателя.

## Статусы и безопасность

| Статус | Значение | Кто переводит |
| --- | --- | --- |
| `awaiting_payment` | Заказ создан, деньги не подтверждены | Бот |
| `payment_reported` | Покупатель сообщил о платеже | Покупатель |
| `processing` | Продавец самостоятельно подтвердил оплату | Владелец |
| `completed` | Продавец подтвердил выполнение | Владелец |
| `cancelled` | Отмена | Покупатель до проверки, либо владелец |

- Заказ по одной и той же Discord interaction идемпотентен. Цена и остаток проверяются повторно перед покупкой; нет покупок отрицательного остатка.
- **Максимум 3 незавершённых заказа на покупателя**; один заказ: до 10 единиц.
- Кнопки и API проверяют Guild ID, владельца заказа и реальные права продавца. Бот не публикует историю заказов в общем канале.
- Список покупателя, номер заказа, товар, сумма, статус, timestamp и факт изменения статуса хранятся в SQLite. **Не сохраняются** банковские данные, Nitro-коды, Discord-токены и тексты личных сообщений.
- Текст пользовательского Discord-аккаунта не нужен для checkout; настройка платежа не должна содержать секреты.
- При недоступных DM статус доступен через `/store my` или `/store order`. При сбое отправки уведомления **заказ остаётся в SQLite**, его видно через `/store orders` или веб-консоль.
- После рестарта публичная панель доступна по постоянным custom_id, а панели до 200 последних ожидающих заказов повторно регистрируются на загрузке. Для более старых заказов есть `/store status` и веб-интерфейс.

## Административные команды

| Команда | Назначение |
| --- | --- |
| `/store add` | Создать товар с ценой в RUB/EUR/USD |
| `/store stock` | Изменить остаток; `-1` = под заказ |
| `/store toggle` | Показать/скрыть товар |
| `/store settings` | Выбрать **закрытый** канал заказов |
| `/store payment` | Инструкция по оплате |
| `/store panel` | Опубликовать витрину |
| `/store catalog` | Открыть каталог без панели |
| `/store my` | Список собственных заказов |
| `/store order` | Просмотр отдельного заказа (только владелец или продавец) |
| `/store orders` | Очередь продавца |
| `/store status` | Ручное подтверждение/закрытие заказа продавцом |

Все админские команды используют существующий `can_manage_settings`; клиентские действия проверяются по Discord user_id и Guild.

## REST API (только локальная консоль)

Новые HTTP-маршруты (password/CSRF), независимы от API экономики NS Coins:

- `GET/POST /api/v1/store/products`
- `GET /api/v1/store/orders`
- `GET /api/v1/store/orders/{id}`
- `POST /api/v1/store/orders/{id}/action`
- `GET/POST /api/v1/store/settings`
- `GET /api/v1/store/analytics`

Статистика агрегирует **только заявки, помеченные выполненными продавцом**, без банковского подтверждения. Суммы разных валют не складываются.

## Схема БД, обновление и откат

Миграция `0018_private_store` создаёт `store_products`, `store_orders`, `store_order_events`, `store_panels`. **Существующие** `economy_shop_items`, `tickets`, `membership_applications` не переименовываются и не меняются; старые покупки NS Coins не затрагиваются.

**Безопасный откат:** остановить бота, восстановить проверенный SQLite-backup сделанный **до** v2.2.0, вернуть код из закреплённого релиза/коммита v2.1.0 и пересобрать контейнер. Записи магазина после резервной копии при этом будут утрачены. **Не запускать `docker compose down -v`**. Не применять `alembic downgrade` на production без полной копии: migration удаляет магазин и все его заказы.
