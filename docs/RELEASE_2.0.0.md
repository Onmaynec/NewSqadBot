# NewSqadBot v2.0.0 — Staff Command Center

Крупный релиз: новый рабочий центр администрации внутри прежней Obsidian Web Console, **без смены фреймворка и без публичного OAuth**.

## Функции

- **Unified Inbox**: единый список текущих заявок, тикетов, жалоб (отдельная категория тикетов) и открытых дел модерации. Фильтры по типу, назначению и поиску; переход в существующий профильный раздел.
- **Мои задачи**: список заявок/тикетов, назначенных локальному оператору, и отдельные задачи со сроками, исполнителем и статусом. Задачи хранятся в SQLite.
- **История сотрудников**: выбор Discord ID и просмотр действий из существующего аудита, истории заявок, модерации и новых квитанций. Этот раздел разрешён только локальному владельцу, не показывает содержимое чата тикетов.
- **Массовые операции**: выбор до 20 заявок, индивидуальное назначение, одобрение или отказ с обязательным подтверждением и причиной отказа. Обрабатываются последовательно; при конфликте/неясном ответе создаётся отдельный отчёт.
- **Шаблоны ответов**: создание/редактирование/удаление шаблонов для тикетов и запросов уточнения заявок. Перед отправкой текст отображается в редактируемом поле, в Discord не отправляется сам по себе.
- **Центр состояния**: Discord Gateway, восстановление соединений, HTTP-ошибки, SQLite, фоновые обработчики, резервные копии и журнал модулей.
- **Аналитика команды**: создание обращений по дням за 7/14/30/90 дней, среднее время первого ответа по доступной выборке и число назначенных заявок/тикетов по сотрудникам.

## Архитектура и надёжность

- Новые `app/web/staff_center.py`, `app/models/staff.py`, `app/web/static/staff.js`, `staff.css`.
- Alembic **0016_staff_command_center** создаёт `staff_tasks`, `staff_templates`, `staff_operations`. Существующие таблицы не удаляются и не сбрасываются.
- **Идемпотентность**: массовая операция и отправка ответа получают случайный ключ; для каждой цели отдельно сохраняется квитанция `processing/success/failed/needs_review` и аудит `origin=local_password`. Повторение с тем же ключом не выполняет внешнее действие.
- **Важно**: Discord API не даёт транзакционного exactly-once. `needs_review` означает, что исход необходимо проверить вручную, прежде чем отправлять новое действие. Квитанция защищает от простого повтора, но не гарантирует отсутствие потери операции при аппаратном сбое.
- Тексты переписки закрытых тикетов **по-прежнему не сохраняются**. В квитанциях только тип операции, результат, время и идентификатор цели.

## Только локальная панель

- Удалены OAuth URL `/auth/discord` и `/auth/callback` и переключатель входа через Discord.
- Парольный PBKDF2-хеш `WEB_ADMIN_PASSWORD_HASH` обязателен. Даже если бот имеет токен, без правильного хеша он не запустится.
- Старые переменные `WEB_DISCORD_CLIENT_ID`, `WEB_DISCORD_CLIENT_SECRET`, `WEB_PUBLIC_URL` должны быть удалены из `.env` или оставлены пустыми; непустые значения отклоняются.
- Панель предназначена для **одного локального оператора** по паролю. Его Discord ID задаётся `WEB_LOCAL_OPERATOR_ID` (или `0` = владелец Guild). Это атрибуция Discord-действий, а не персональная авторизация.
- Доступ к сайту снаружи не поддерживается. Compose публикует веб-порт исключительно на `127.0.0.1`.
- Если ранее был настроен **Tailscale Funnel, обязательно выполните `tailscale funnel off` на хосте** и проверьте отсутствие публичного проксирования. Программа не может отключить инфраструктуру Funnel автоматически.

## Обновление из v1.9.0

1. **Сделайте резервную копию до обновления**:
   ```powershell
   docker compose exec bot python -m app.ops.backup create
   ```
   Проверьте экспорт копий за пределы Docker volume.
2. Выключите публичный Tailscale Funnel на компьютере, где работает бот:
   ```powershell
   tailscale funnel off
   ```
   Убедитесь, что больше нет публичных hostname и перенаправления на порт панели.
3. В `.env` удалите старые настройки OAuth и Tailscale. Укажите `WEB_ADMIN_PASSWORD_HASH`, `WEB_LOCAL_OPERATOR_ID=0` или Discord ID администратора. Пароль длиной от 14 символов; создайте хеш через `python -m app.web.auth hash` внутри контейнера.
4. Обновите код и запустите:
   ```powershell
   git pull origin main
   docker compose up -d --build --force-recreate
   docker compose logs --tail=200 bot
   ```
5. Подключайтесь локально: **http://127.0.0.1:8787**. Выйдите из старых вкладок (OAuth-сеансы больше не работают).
6. Проверьте миграцию SQLite 0016 и новые таблицы:
   ```powershell
   docker compose run --rm --no-deps --entrypoint python bot -m app.ops.smoke
   ```
7. Создайте тестовую задачу, шаблон, откройте единую очередь, выполните безопасное назначение одной заявки и проверьте журнал аудита.
8. Не используйте `docker compose down -v`: это удалит volume с SQLite.

## Приёмка

- [ ] Python lint/pytest, Node syntax/runtime, Docker smoke (пустая база и миграции), Security и Playwright Chromium — **зелёные**.
- [ ] Вход по локальному паролю работает, `/auth/discord` и `/auth/callback` возвращают 404, внешний Host блокируется, при неверном CSRF запись не происходит.
- [ ] Веб-панель и новая навигация не зависают; Ctrl+K находит все новые разделы.
- [ ] Unified Inbox объединяет заявки, тикеты, жалобы и дела только текущего Guild; фильтры корректны.
- [ ] Задачи, шаблоны и квитанции сохраняются после перезапуска контейнера.
- [ ] Массовые действия идут последовательно; повтор с тем же ключом не выполняет Discord-публикацию дважды; ошибки видны оператору.
- [ ] Шаблон не отправляется без явного подтверждения; содержимое можно изменить перед отправкой.
- [ ] Операции в Discord с отозванными ролями/правами корректно сообщают о проблеме и не выдают ложный успех.
- [ ] Нет OAuth-полей/кнопки входа и публичного Tailscale-адреса.
- [ ] Backup/restore-probe v1.9.0 остаётся рабочим после миграции.
- [ ] Снимок экрана и ручная проверка в браузере на Windows, Firefox/Chromium, с настоящим Discord Guild.

## Ограничения

- Это локальная административная консоль **с одним паролем**, а не несколько персональных паролей сотрудников. «Мои задачи» относятся к указанному локальному Discord-оператору.
- Для действий в Discord оператор должен существовать на сервере, а Gateway должен быть доступен. В режиме offline доступен просмотр SQLite и диагностики.
- Персональные Staff Timeline не дают права сторонним пользователям посмотреть чужой журнал; весь сайт доступен только владельцу пароля. Не распространяйте пароль среди сотрудников.
- Квитанции Staff Center защищают от повтора с тем же ключом, но не заменяют проверку результата внешних Discord-операций.
